# Table

The data table: plain semantic markup with shadcn styling and three options, `density`, `layout` and `stack`, plus a floor width set through `className`. From `@pts/ui/table`.

**Look:** `text-sm`, rows `border-b hover:bg-muted/50`, selected `bg-muted`. `TableHead` is `h-10 px-2 font-medium text-foreground`; `TableCell` is `p-2` around a 28px content box. `density="compact"`: heads `h-8 text-xs`, cells `px-2 py-1.5`. `TableFooter` is `bg-muted/50 border-t font-medium`. Cells are `whitespace-nowrap`.

**Phones (`stack`):** below `md` a stacked table drops its header and turns each row into a compact card: the first cell is a full-width title line and the rest wrap beneath it. The title line is the first real cell: the bulk select column (`data-slot='table-select-cell'`) is hidden there and skipped (the `first-cell` variant). Pass `label` to a cell whose value needs a name once the header is gone ("Hours", "Last sign-in"); self-describing values (badges, icon + text) go without. Give the actions cell `max-md:ml-auto`, and drop an empty cell with `max-md:hidden` rather than showing a lone dash. A cell that should lead the card instead of the first one takes `max-md:order-first max-md:basis-full` (the first cell then needs `max-md:first-cell:basis-auto`).

**Tablets and small laptops (floor width):** from `md` up a fixed-layout table keeps its columns, and with the sidebar open the content area is only about 30rem wide at 768px and 47rem at 1024px. Percentage widths shrink with it while cells stay `whitespace-nowrap`, so columns overprint. A table that doesn't fit gives itself a floor with `md:min-w-[…]` on `Table`, the narrowest width at which its columns hold their content (with headroom: real phone numbers, totals and names run longer than the fixtures), and below that it scrolls sideways inside its card. The floor never applies to a stacked phone layout, and it must stay at or under the table's width at 1440px with the sidebar open (72.75rem), so wide screens don't change. Current floors: companies 72rem; time logs 64rem; invoices and submissions archive 60rem (its Archived column takes the room Company would need, so the archive keeps Company and the source detail hidden until `2xl` and gives its Outcome and Source columns smaller shares); people 56rem; lead archive 52rem; submissions and projects 50rem; product catalog 48rem; hour blocks 42rem; project archive 40rem. Tax rates fits without one.

**Rules**

- Every list table sets `stack`. A grid read across its columns (the monthly close payouts) keeps its columns instead and scrolls inside its card from a floor width. (guard: review)
- Every `layout='fixed'` table whose columns overprint at 768px with the sidebar open sets an `md:min-w-[…]` floor (see above). Measure it rather than guess: widen the table in devtools until no cell's content spills, then round up. Card stacking stays below `md`; extending it to `lg` wouldn't help, since `lg` starts at 1024px, where the clients table already overprints. (guard: review)
- Every sortable table sets `layout='fixed'` and puts `truncate` on long-text cells, so sorting and paging can't make columns jump. (guard: review)
- **Only the select box and Actions are fixed.** In a `layout='fixed'` table the select box and the Actions column take a fixed width (`w-8`, `w-16`, `w-24`, …) and never grow. The main text column (names, the project) has no width and takes what is left; every other column takes a `%` share, set so it holds its content at the table's floor width: share = px it needs ÷ floor, where the px it needs is the wider of the header (sort arrow included) and the widest value, plus the cell padding. Add headroom only where real values run longer than the fixtures (money, phone numbers, invoice numbers, long badges). Wider screens then widen every data column a little instead of opening one big gap. With every column sized, a fixed table spreads its extra width over all of them, the select box and Actions included. (guard: eslint `pts/fixed-table-columns`)
- **One row height.** Every list row, group rows included (a client heading on Projects), is the shared `TableCell` height: a 28px content box (`box-content h-7`) plus its padding and the row border, so 41px compact and 45px default whatever the row holds (a cell's height is its minimum: text-only and group rows match rows with 28px buttons). Never set `py-*`, `p-*` or `h-*` on a row's cells to change it; above `md` only empty-state rows (`colSpan`, `p-4`) differ. Shown on `/design#tables`. (guard: review)
- Numbers (hours, money, counts) are right-aligned with `tabular-nums`; the check covers cells that print `formatCurrency`, `formatHours` or `formatPercent`. (guard: eslint `pts/figure-cell-aligned`)
- Dates render through `formatCalendarDate` ("Sep 23, 2026"). (guard: eslint `pts/dates-through-ui`)
- Lists with an Archive or Restore row action lead with the bulk select column (`bulk-select.md`). (guard: review)
- Row actions are `RowActionButton`s (every icon-only one, so each has a hover tooltip) or a DropdownMenu; in-row toggles may apply instantly (unlike sheet controls). (guard: eslint `pts/no-title-tooltip`; review)
- **A linked record opens in place.** A record named in a cell (the Client on an hour block, the Company on a person, a task on a time log) or in a hover-card row opens its sheet over the list you're on, stacked like any sheet, never by going to the record's own list. The link is `SheetLink` (`components/ui/sheet-link.tsx`, look `cellLinkClass`); on a card or meta line it's `MetaLink` with `sheet`, in a hover card the row's `sheet`. A new-tab click opens the same list with the sheet open. The same goes for cards and home widgets. The one exception is a project: its name opens its task board, where its work lives. (guard: eslint `pts/sheet-link-in-place`)
- Page counts come from `PageShell` ("Showing 24 of 118 clients"); empty states are one sentence ("No matching tasks."). (guard: review)

## LinkedRecordsHoverCell

`components/ui/linked-records-hover-cell.tsx`: a count in a table cell (people on a company, projects on a client, tasks on a time log). Hovering or focusing it opens a card listing the records behind it; each row opens its record's sheet over the page (`sheet`); `href` is only for a record with no sheet. A zero is the shared dash with no card; a single record can use a lone icon `trigger` (with `ariaLabel`). `withIcon` puts the entity icon before the count, as list columns do.

**Use it** in list tables, where a row has room for one number. In a sheet, show the records themselves as cards with `EntityList` / `SheetRecordList` instead: a sheet is where you work with them, a table is where you glance. (guard: review)

## Footer

Every paged list ends in `PaginationControls mode='paged'` (`components/ui/pagination-controls.tsx`): rows per page on the left, "1–25 of N" and the pager on the right. A list with a list-wide figure passes it as `summary`, which sits centred between them (Time logs: "Total: 710.5h", the hours across every filtered page). Lists without such a figure leave it out; the count is not repeated there.
