# Select

A single-choice dropdown on Base UI Select with a Radix-shaped API (`onValueChange(value: string)`). From `@pts/ui/select`.

**Parts:** `Select`, `SelectTrigger` (`size="sm" | "default"`: h-8 / h-9), `SelectValue` (placeholder in `muted-foreground`), `SelectContent`, `SelectGroup`, `SelectLabel` (text-xs muted), `SelectItem`, `SelectSeparator`.

**Look:** trigger matches Input (border-input, shadow-xs, rounded-md, ChevronDown at 50%). Popup: `bg-popover border rounded-md shadow-md p-1`, at least the trigger's width. Items: `rounded-sm py-1.5 pl-2 pr-8 text-sm`, Check indicator on the right.

**Rules**
- The popup is left-aligned with its trigger by default (`align='start'` in the wrapper). Never pass `align='start'` at a call site; pass another `align` only when deviating on purpose.
- Items need `hover:bg-accent hover:text-accent-foreground` alongside `data-highlighted:` — Base UI doesn't set `data-highlighted` on plain mouse hover. The wrapper already does; keep both if you restyle.
- Inside a sheet, a Select change is a form value applied on Save, never an immediate mutation.
- **An "Add …" picker hangs from its button.** A `SearchableCombobox` with a custom `trigger` (the + / Add button at the right of a section heading: Members, People, repositories) opens with its right edge on the button's, just below it, inside the content column; a field opens under its left edge. Option avatars carry a hairline ring so the circle shows on a highlighted row. (guard: review)
- **Entity picker fields.** A picker for an entity (person, company, client, project, task; assignee, owner, member, originator and closer are a person) leads its label with that entity's registry icon in its colour: `FormLabel entity='company'`, or `EntityFieldLabel` (`components/ui/entity-label-icon.tsx`) outside react-hook-form; an "Add …" picker's section title takes the same icon (`SheetSection icon`). The icon is `aria-hidden`, so the label still names the field. Inside the picker, a person shows their own avatar in each option and in the trigger: a sign-in passes `userId`, anyone else `avatar: { src: personPhotoSrc(…) }` (photo, else initials); never a generic person glyph. A picker whose options are all one entity (companies, clients, projects) shows no icon in its options or trigger: the label carries it. A one-off option ("Unassigned") may keep an icon. Sweep for them when you add a sheet or dialog. `/design#pickers`. (guard: review)
- For long or searchable lists use `SearchableCombobox` (`components/ui/searchable-combobox.tsx`). Its picked option has a check on the right; no row keeps a left gutter for it. List filters: `filter.md`.
- **A picker opens on its selection.** The selected option is scrolled into the middle of the list, checked, and highlighted, so arrows and Enter start there; a multi-select opens on its first ticked option. It happens once per open: scrolling and hovering afterwards are left alone, and typing a search highlights the top match. A hand-built cmdk picker gets this from `useRevealSelected` in `components/ui/command.tsx` (its list `ref`, plus the same value as the `Command`'s `defaultValue`).
- Every floating panel (this list, popovers, menus, date pickers) uses `shadow-popover`.
- **"When does this take effect" is `EffectiveMonthSelect`** (`components/billing/effective-month-select.tsx`): a tinted callout, title left, a `w-72` month select right, one optional note line. Billing starts/stops, billing type and commission changes, and a sign-in's role change all use it. Month labels come from `lib/billing/months.ts` (`monthLabel`, `monthLabelFromNow`, `currentMonthStartUtc`), counted in UTC like the server.
