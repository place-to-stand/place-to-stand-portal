# Bulk select

Tick rows in a list, then act on them together. From `components/table/bulk-select`: `useRowSelection`, `RowSelectionProvider`, `SelectAllHead`, `SelectRowCell`, `BulkActionBar`. Shown on `/design#bulk-select`.

**Look:** a 32px leading column (`w-8 pl-2`): 8px from the table edge to the box, like every cell's left padding on every list whose rows can be archived. Each row's 16px `Checkbox` stays hidden until the row is hovered or focused; the header box always shows, centred in the header row. Once one row is ticked every box shows, ticked rows take the shared selected tint (`data-selected`, `bg-muted`), and the bulk bar rises at the bottom centre: "3 companies selected", then the list's own actions (outline, e.g. Submissions' Acknowledge), then Archive (destructive) on an active list or Restore (outline) on an Archive tab, then a clear ×. Phones have no hover and little room, so below `md` the column is hidden and an unread row keeps its tint.

**Unread rows** share the column: the dot sits where the box will be and gives way to it on hover. The row carries `UNREAD_ROW_CLASS` (`lib/table/unread-row.ts`: medium weight on a `bg-muted/50` tint that deepens to `muted/75` on hover; ticked, it takes the full selected `muted`), so it still reads as unread while the dot is hidden.

**Selecting:** a click anywhere in the cell ticks the row and never opens it; shift-click ticks a range. The header box ticks the page (or clears it when the page is all ticked). With the whole page ticked and more rows matching, the bar offers "Select all 118 people" (an outline button with a double check): every row matching the filters, on every page, offered only up to 500 rows (more asks you to narrow the filters). Unticking any row drops back to the page's ticks. Ticks clear when the page's rows change (paging, filtering, a refresh after the action). A list split into several tables (Projects) passes each table's ids to `SelectAllHead ids={…}`.

**Acting:** `bulkSetArchived` (`app/(dashboard)/_actions/bulk-archive.ts`) runs each row through the same archive or restore its row button uses (`BULK_ARCHIVE_REGISTRY`), up to 500 rows, so every rule, refusal and activity entry matches. The bar resolves "all matching" to ids first (`resolveBulkMatchingIds`), then sends them 25 at a time (`runInChunks`, `lib/bulk/run-in-chunks.ts`) so no call nears the function time limit; a call that fails stops the run with an "Unable to …" toast, refreshes the list to show what changed, and never replaces the page with the error screen. Archive confirms first with the shared `ArchiveConfirmDialog` (`many`); restore runs at once, like the row button. One toast reports the result: "12 companies archived", or "10 companies archived, 2 not" naming the refused rows and why. Closed-month notes follow as their own warning toast.

**List actions:** a list can add its own bulk actions through `BulkActionBar actions` (`BulkBarAction`: label, icon, the verb for the toasts, and a server action taking the selection). Each runs its row action per row with the shared `runBulk` and `resolveBulkIds` (`app/(dashboard)/_lib/`). Submissions has one: Acknowledge (`bulkAcknowledgeSubmissions`), which sends each ticked row's version as rendered, so a row that changed since is refused rather than acknowledged unseen.

**Boards** (project board, My tasks, Leads) select cards instead of ticking rows, through `useBoardSelection`, `BoardSelectionProvider` and `useSelectableCard` (`components/board/board-selection.tsx`; pure helpers in `lib/dnd/board-selection.ts`). Shift-click picks a range down one column (across columns it picks just the card), ⌘-click (Ctrl on Windows; on a Mac Ctrl-click stays a right click) adds or drops one card. A plain click still opens the card, as a list row's click does, and opening a card outside the selection clears it. A selected card takes the primary border with a 1px ring and a 5% primary fill (`BOARD_CARD_SELECTED_CLASS`), and screen readers hear "Selected". Escape or a click away from the cards and the bar clears the selection (unless a sheet, dialog or menu takes it), and a card that leaves the board (a filter, a refresh) leaves the selection. Only people who can act on the cards can select them. `BoardBulkBar` (`components/board/board-bulk-bar.tsx`) is the same `BulkActionBar` with the card menu's actions: **Set assignee ▾** and, for tasks, **Set due date ▾** (Today, Tomorrow, Next Monday, a calendar, Clear) and **Mark as done** (the card menu's own move to the top of Done, through the board's drop path; disabled when every selected task is done already), then Archive. They run each card through the card menu's own save (`bulkSetTaskAssignee`, `bulkSetTaskDueDate`, `bulkSetLeadAssignee` in `app/(dashboard)/_actions/board-bulk.ts`; archive through `BOARD_BULK_ARCHIVE`). Archive and due dates show on the board at once and put back any card the save refused (archived cards stay selected, so the bar shows the save until it lands); the toast names refused cards, as on lists. Set assignee and Set due date keep the cards selected afterwards, so a second change needs no reselecting; Archive clears them, as they leave the board. Who can take a task depends on its project (or lead), so Set assignee offers only the people who can take every selected task. Boards never offer "Select all N".

**Rules**

- Every list whose rows can be archived or restored has the select column as its first column, through `SelectRowCell` and `SelectAllHead`; never a hand-rolled checkbox column. (guard: review)
- An unread marker lives in the select column (`SelectRowCell unread`), never in another cell, and its row carries `UNREAD_ROW_CLASS`. (guard: review)
- A bulk action reuses the single-row action for each row; it never writes the table itself. (guard: review)
- Board cards select through `useSelectableCard`: Shift for a range in a column, ⌘ or Ctrl for one card; a plain click always opens the card. Never a checkbox on a card. (guard: review)
- A board's bulk bar offers the same actions as its card menu, no more, through `BoardBulkBar`. (guard: review)
- Adding a list: add its words to `BULK_ARCHIVE_ENTITIES`, its matching query and row action to `BULK_ARCHIVE_REGISTRY`, then the three components; add one to the empty-state `colSpan`. (guard: review)
